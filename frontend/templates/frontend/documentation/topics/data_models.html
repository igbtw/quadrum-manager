{% blocktrans trimmed %}The application keeps a compact data model: nine entities covering the catalog, sales, stock auditing, receivables, and onboarding state. This page is a quick map; the schema, constraints, and migration guidance live in docs/data-model.md.{% endblocktrans %}

{% blocktrans trimmed %}Entities{% endblocktrans %}

{% blocktrans trimmed %}Model{% endblocktrans %}{% blocktrans trimmed %}Purpose{% endblocktrans %}
Category{% blocktrans trimmed %}Groups products; referenced with PROTECT so a category in use cannot be deleted.{% endblocktrans %}
Product{% blocktrans trimmed %}Name, code, category, price, cost, stock, minimum stock, and active flag.{% endblocktrans %}
Person{% blocktrans trimmed %}Customer registry with type, record/doc, contact fields, and active flag.{% endblocktrans %}
Sale{% blocktrans trimmed %}Sale header: code, status, payment method, totals, customer, responsible user, and idempotency key.{% endblocktrans %}
SaleItem{% blocktrans trimmed %}One line of a sale with the captured unit price at sale time.{% endblocktrans %}
StockMovement{% blocktrans trimmed %}Append-only audit log of every stock change (sale, return, adjustment), with optional sale and user links.{% endblocktrans %}
AccountReceivable{% blocktrans trimmed %}Amount owed by a person for an On Account sale.{% endblocktrans %}
Payment{% blocktrans trimmed %}A payment applied to a receivable.{% endblocktrans %}
OnboardingProgress{% blocktrans trimmed %}First-run guide state per account, including the resume step.{% endblocktrans %}

{% blocktrans trimmed %}Business rules the application enforces{% endblocktrans %}

  • {% blocktrans trimmed %}Stock is never allowed to go negative — a database constraint backs the service-level checks.{% endblocktrans %}
  • {% blocktrans trimmed %}Payments never exceed the outstanding balance, and cancelled receivables refuse new payments at multiple layers.{% endblocktrans %}
  • {% blocktrans trimmed %}A completed sale keeps its captured prices; later catalog changes do not rewrite its history.{% endblocktrans %}
  • {% blocktrans trimmed %}Product and person records referenced by sales are protected from deletion (PROTECT); the sale keeps a nullable link if a customer is removed (SET_NULL).{% endblocktrans %}
  • {% blocktrans trimmed %}Monetary values keep two decimal places.{% endblocktrans %}
  • {% blocktrans trimmed %}Stock movement history is append-only, so stock changes can always be reconstructed.{% endblocktrans %}
