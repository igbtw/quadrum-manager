{% blocktrans trimmed %}Products form the catalog that feeds the point of sale. The Products page manages the catalog; the Inventory page shows stock and records adjustments.{% endblocktrans %}

{% blocktrans trimmed %}Product fields{% endblocktrans %}

{% blocktrans trimmed %}Field{% endblocktrans %}{% blocktrans trimmed %}Meaning{% endblocktrans %}
name{% blocktrans trimmed %}The product name shown in the catalog and sale screens.{% endblocktrans %}
code{% blocktrans trimmed %}A unique short code used for lookup (for example, COX-01).{% endblocktrans %}
category{% blocktrans trimmed %}The grouping used to filter the catalog and the point-of-sale product picker.{% endblocktrans %}
price{% blocktrans trimmed %}Sale price (R$, two decimals). The POS always uses this stored price.{% endblocktrans %}
cost_price{% blocktrans trimmed %}Optional acquisition cost for reference.{% endblocktrans %}
stock_quantity{% blocktrans trimmed %}Current stock. Never allowed to be negative.{% endblocktrans %}
minimum_stock{% blocktrans trimmed %}Alert threshold used by the low-stock indicator.{% endblocktrans %}
active{% blocktrans trimmed %}Inactive products stay in history but are hidden from sale selection.{% endblocktrans %}

{% blocktrans trimmed %}Stock status indicators{% endblocktrans %}

  • {% blocktrans trimmed %}Normal — stock is above the minimum.{% endblocktrans %}
  • {% blocktrans trimmed %}Low — stock is above zero but at or below the minimum stock threshold.{% endblocktrans %}
  • {% blocktrans trimmed %}Out of Stock — stock is exactly zero; the product cannot be sold.{% endblocktrans %}
  • {% blocktrans trimmed %}Inactive — the product is deactivated; its stock is not part of the active counts.{% endblocktrans %}

{% blocktrans trimmed %}Adjusting stock{% endblocktrans %}

    {% url 'frontend:inventory' as _u1 %}
  1. {% blocktrans trimmed %}Open Inventory and use the stock adjustment form.{% endblocktrans %}
  2. {% blocktrans trimmed %}Pick the product, enter the quantity — positive to add stock, negative to remove — and a reason.{% endblocktrans %}
  3. {% blocktrans trimmed %}Submit. The new stock level is saved together with a stock movement recording the signed quantity, the reason, and the responsible user.{% endblocktrans %}
  • {% blocktrans trimmed %}Stock never goes negative: an adjustment that would remove more than the available quantity is rejected with an error message, and nothing is saved.{% endblocktrans %}
  • {% blocktrans trimmed %}Every change is an append-only audit trail; sales produce negative movements, cancellations produce returns, and manual adjustments are recorded as adjustments.{% endblocktrans %}
  • {% blocktrans trimmed %}Zero-quantity adjustments are rejected.{% endblocktrans %}

{% blocktrans trimmed %}Movement types, locking behavior, and the negative-stock constraint are detailed in docs/business-flows.md and docs/data-model.md (repository files, not served by the application).{% endblocktrans %}
