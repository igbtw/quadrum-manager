{% blocktrans trimmed %}Sales are recorded at the point of sale and listed in the Sales history. Each sale stores its line items, totals, payment method, customer (when attached), and the responsible user.{% endblocktrans %}

{% blocktrans trimmed %}Recording a sale{% endblocktrans %}

    {% url 'frontend:point_of_sale' as _u1 %}
  1. {% blocktrans trimmed %}Open New Sale and pick products by category with the quantity controls.{% endblocktrans %}
  2. {% blocktrans trimmed %}Review the cart total. Prices and totals are always calculated from the stored product price.{% endblocktrans %}
  3. {% blocktrans trimmed %}Choose the payment method and select Finalize Sale.{% endblocktrans %}
  4. {% blocktrans trimmed %}The sale is recorded as Completed, stock is deducted from each product, and a stock movement is written per item.{% endblocktrans %}

{% blocktrans trimmed %}Payment methods{% endblocktrans %}

  • {% blocktrans trimmed %}Cash, Debit, Credit, and PIX close the sale immediately.{% endblocktrans %}
    • {% url 'frontend:documentation_topic' 'finance' as _u1 %}
  • {% blocktrans trimmed %}On Account records the sale and, when the sale has a customer attached, creates an account receivable for that person — managed on Finance. An On Account sale without a customer completes but creates no receivable.{% endblocktrans %}

{% blocktrans trimmed %}Sale states{% endblocktrans %}

  • {% blocktrans trimmed %}Pending — created but not finalized (not the normal outcome of the checkout flow).{% endblocktrans %}
  • {% blocktrans trimmed %}Completed — finalized; stock was deducted and the total recorded. Completed sales keep their history.{% endblocktrans %}
  • {% blocktrans trimmed %}Cancelled — a cancelled sale remains visible in history; when applicable, stock is restored and its receivable is closed. See docs/business-flows.md for the exact cancellation restrictions (for example, a receivable that already has payments blocks cancellation).{% endblocktrans %}

{% blocktrans trimmed %}Validation and safe retries{% endblocktrans %}

  • {% blocktrans trimmed %}Quantities must be positive whole numbers; invalid items are rejected before anything is written.{% endblocktrans %}
  • {% blocktrans trimmed %}A sale that would consume more stock than available is rejected and nothing is saved — stock never goes negative.{% endblocktrans %}
  • {% blocktrans trimmed %}Finalizing uses an idempotency key: if the same submission is retried (for example after a network hiccup), the existing sale is returned instead of creating a duplicate. Reusing a key with different contents is rejected with a conflict.{% endblocktrans %}
